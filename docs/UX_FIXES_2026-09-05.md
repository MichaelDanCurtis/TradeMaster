These changes resolve the worker-startup and account-baseline blockers and additional ticket, credential-discovery, and backup defects. The subsequent [execution scheduler](EXECUTION_SCHEDULER.md) adds reviewed TWAP/DCA paper execution, and [Codex research integration](CODEX_RESEARCH.md) adds ChatGPT-sign-in research with an explicitly reviewed subscription policy.

## Fixed and verified

- **Local services:** `npm run dev:local` starts the API, web, durable research worker, and deployment observation/evaluation worker. The command requires API-visible worker heartbeats before reporting success. `npm run stop:local` stops all four and allows worker cleanup first. All processes use the same configured database and artifact directory. Research workers load the configured environment before resolving provider secrets; offline calculation children still receive no provider credentials.
- **Account baseline:** Alpaca's cent-reported USD equity can reconcile against its detailed marked positions only when the reported figure equals those details rounded to cents. Other sources, ledger cash, and share quantities retain their strict tolerances. Raw broker values remain unchanged. Reconciliation exposes each reporting residual and the period change separately from strategy attribution. Accounting build fingerprints include the precision policy.
- **Actual account check:** the normal browser now opens the previously failing baseline preview at $100,821.86, with its $0.004229 reporting residual and five positions displayed. The preview was dismissed; no baseline was approved. Workers correctly report `baseline_review_required` until the user accepts a starting snapshot.
- **Manual order tickets:** preparing a ticket no longer launches a research/model run. Minimal manual bookkeeping is created atomically with a successful exact-order preview and is excluded from research history and latest committee verdicts. Existing paper approval, risk and submission checks still apply. Changing ticket inputs invalidates the displayed preview and discards late responses for earlier inputs.
- **Model discovery:** API-provider model discovery resolves the saved credential reference instead of looking for an inline key that provider-config sanitization removes. Tests verify the key reaches the discovery adapter and never appears in the response.
- **Research-provider explanation:** Codex's existing adapter strips output-token caps. Automated bounded design/extraction continues to reject it and now explains the specific limit and corrective action. Existing Codex assignments and model choices were preserved. A supported API provider/key is still needed for those roles; no metered completion was launched during this follow-up.
- **Backups:** new encrypted backups include the consistent SQLite image and content-addressed research artifacts. The database is copied before artifact enumeration, preserving already-persisted references to immutable files. Corrupt artifacts fail backup creation. Credentials and backup keys remain separate. Legacy manifests and earlier database-only backups retain their original scope.
- **Recovery:** the new recovery command decrypts and verifies every file, checks SQLite integrity, and writes only into a new destination. Existing directories cannot be overwritten. A round-trip test restored a database reference and then loaded the referenced research artifact from the recovered store.
- **Plan labels:** the adaptive-limit catalog entry now discloses its market fallback; the entry-bracket preview is no longer labeled as a standalone stop loss. These remain analytical plans. The separately approved manual ticket does not execute a multi-leg plan or schedule.
- **Default tests:** retained the existing real-research defaults and broker-disabled default. Updated stale assertions and removed an outdated claim about model availability. Also aligned the worker's unconfigured-broker assertion with the explicit HTTP failure introduced by the previous audit.

## Local commands

```sh
npm run dev:local
npm run stop:local
```

Optional local overrides: `TRADINGAGENTS_UI_DATABASE_URL`, `TRADEMASTER_RESEARCH_ARTIFACTS`, `TRADEMASTER_API_PORT`, `TRADEMASTER_WEB_PORT`, and the four `TRADEMASTER_*_SESSION` variables. Workers run in tmux and persist while the local machine is running; this is not an operating-system boot service or remote deployment.

Recover a backup with a configured key reference (the destination must not exist):

```sh
.venv/bin/python -m tradingagents.ui.restore_backup "/absolute/path/snapshot.tmbackup" "/absolute/path/recovered-workspace" --key-ref env:TRADEMASTER_BACKUP_KEY
```

Recovery does not start services or change the current installation. The recovered database is `database.sqlite`; research files are under `.research-artifacts`. The settings export, provider credentials, backup key, offsite upload, scheduled backups, and automatic key recovery are separate concerns. The web button verifies backup integrity; it does not perform recovery.
